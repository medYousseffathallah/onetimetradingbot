# Third-party adoption gate

Audit one repository or skill at a time, in an isolated reference directory outside the
application import path. Never run its setup hooks, browser automation, notebooks, or shell
scripts before review. Do not import unknown code just to inspect it.

Record repository URL, immutable commit, license and attribution obligations, maintainer
activity, Python/runtime compatibility, external endpoints, secret handling, install scripts,
model/data download sizes, transitive dependencies, and reproducible tests. An absent license
is not permission to copy. Source access permission is not data redistribution permission.

For trading repositories, also check data dates/vintages, train/test splits, fill assumptions,
corporate actions, universe construction, fees, stale prices and claimed performance evidence.
A third-place hackathon result, stars, dashboard, or model accuracy is not trading validation.

Adopt the smallest useful component behind an adapter. Record ADOPT / REFERENCE ONLY /
REJECT with reasons. Do not fork a full microservice stack to reuse one scraper. Never
carry an author's advertised returns into our experiment registry as our measured results.

The local-market repositories mentioned earlier in the conversation are unreviewed candidates,
not dependencies of this starter. Nothing from them has been copied into the delivered code.
