# M14 next research gates

## Present decision

Keep Model G, sparse research and any proposed v2 engine **research-only**.
No new production strategy was promoted. Correct code and reproduced historical
numbers are necessary but do not establish predictive edge.

## Required next evidence

1. Independently verify corrected identities, holding studies, cutoff invariance,
   matched benchmarks and denominator definitions using the final source manifest.
2. Review date-specific Challenge membership assumptions; a current saved registry
   does not independently establish historical admission or delisted coverage.
3. Obtain permitted, timestamped financial disclosures and corporate-action records.
   Source homepages, static catalogs and LLM recollections are not ingested evidence.
4. Resolve official competition rules and account/order/history acceptance separately.
   Research assumptions cannot close rule gaps or confirm pending account captures.
5. Freeze a genuinely prospective, append-only signal protocol before unseen bars
   arrive. Existing November outcomes and the proposed Oct13–Nov10 period are
   contaminated historical evaluation, not a pristine holdout.
6. Predeclare v2 hypotheses, units, missingness semantics, costs, exact entry/exit
   feasibility, purging/embargo, cohorts, trial counts and rejection criteria. Fit
   any transforms using training data only. Reject a candidate when evidence fails.
7. Require phase and outlier robustness plus an executable, exposure-matched
   benchmark; raw return comparisons with different cash use are insufficient.

## Next proposed experiment: directional awakening, version1

Experiment ID proposal: `m14_v2_directional_awakening_v1` (not implemented/promoted).
Compare the corrected sparse baseline with one change: an awakening can become a
selected candidate only when its **observed, available latest-session return is
strictly positive**. Keep the existing frozen turnover trigger and all other
parameters; zero/unknown returns fail this directional condition. This sign-based
test introduces no winner-fitted positive-return threshold. Missing transaction
counts stay unknown; a separate trade-count hypothesis requires a verified source
adapter and its own registry entry.

Predeclare executable-sample FPR as the primary diagnostic and report coverage,
selection counts, unknown outcomes, missed executable winners, capacity and
precision alongside it. Both arms use the same costs, scope, target capital,
decision/entry/exit timing and known-outcome denominator. Use already-observed
history only for retrospective bug/execution checks. Lock code/data/config/signal
hashes before the first genuinely future verified session, then collect60 future
verified sessions with fixed10-session, non-overlapping outcome blocks. No tuning
or parameter changes after lock; no assumption that60 sessions gives sufficient
statistical power. Failure to improve, or excessive coverage loss, rejects the
candidate. A valid joint cash timeline and independent review remain prerequisites
for any portfolio-return or promotion claim.

Authenticated Browser Companion capture, movement history and pending-order
verification remain operator-assisted work. Fixture browser tests cannot substitute
for that acceptance. No pending synchronization or trade is confirmed in this sprint.
